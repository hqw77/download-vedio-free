## 2. 学习主线：不要按目录从头读到尾

按目录读会陷入“每个文件都看了，但串不起来”。建议只跟三条线：

1. **下载线**：`HeroSection → App.handleParse → /api/parse → downloader/douyin → VideoResult → /api/download`
2. **AI 线**：`VideoSummary.onMounted → /api/summarize → 配额 → 字幕 → DeepSeek 流 → SSE → marked/markmap`
3. **账号与钱线**：`AuthModal → JWT → 配额 → Pricing → Stripe Checkout → Webhook → VIP`

每读完一段，问自己三个问题：

- 这一步的输入/输出是什么？
- 失败时会发生什么（降级/报错/白扣额度）？
- 如果流量 ×100，哪里先崩？

4. **配额并发实验**（不花 token，直接测 DB 函数）：

```python
# 在 backend 目录下运行；先确保 users 表里有 id=1 的用户
from concurrent.futures import ThreadPoolExecutor
from database import check_and_increment_summary

def hit(_):
    try:
        return check_and_increment_summary(1)[0]
    except Exception as e:
        return f"ERR:{e}"

with ThreadPoolExecutor(max_workers=10) as ex:
    results = list(ex.map(hit, range(20)))
print("allowed:", sum(r is True for r in results), results)
```

   观察是否出现超过 3 次 `True`（也可能先看到 `database is locked`，这同样说明并发写没有排队）。

|---|------|------|----------|----------|
| E1 | SSE 换行拆帧 | 后端 summary 事件去掉 `json.dumps` | 含换行的 token 被拆成多帧/丢内容 | 为什么 JSON 编码 |
| E2 | 事件循环阻塞 | 总结进行中反复请求 `/api/health` | 健康检查延迟明显升高 | P0-2 |
| E3 | 配额超发 | 20 线程并发调 `check_and_increment_summary` | 出现 >3 次 allowed | P1-2 |
| E4 | chat 未鉴权 | 不带 token 调 `/api/chat`，传 `subtitle_text` | 仍能拿到回答 | P0-1 |
| E5 | 缩略图 SSRF | `GET /api/proxy/thumbnail?url=http://127.0.0.1:8000/api/health` | 返回内网接口内容 | P0-3 |
| E6 | Webhook 重放 | Stripe CLI 重发同一事件 | 订单不重复、VIP 不叠加 | 幂等设计 |

E4 的请求示例（避免触发字幕提取，直接传文本）：

```powershell
$body = @{ url = "https://example.com/v"; question = "说了什么"; subtitle_text = "这是一段测试字幕" } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8000/api/chat -Method Post -ContentType "application/json" -Body $body
```

> 注意：E2/E4 会消耗少量 token；E3/E5 不花钱；E6 用测试模式。

## 7. 改造清单（挑 1–2 个做，面试含金量最高）

### 改造 A：把总结流改成真异步（推荐，2h）

- 用 `AsyncOpenAI` 替换 `OpenAI`，`async for chunk in await client.chat.completions.create(..., stream=True)`。
- 把 `summarize_stream` / `chat_stream` 改成 async 生成器，`api_summarize.py` 里 `async for`。
- 验收：两个并发总结时，`/api/health` P95 仍 < 100ms；代码 diff 约 30 行。
- 面试话术：“我发现 SSE 生成器里在同步迭代 OpenAI 流，导致事件循环被占住；换成 AsyncOpenAI 后并发不再串行。”

### 改造 B：补齐 chat 鉴权与配额（1h）

- 复用 `_check_summary_permission`，未登录返回 `need_login`，超限返回 `need_vip`。
- 前端 `sendQuestion` 处理这两类错误，弹登录/升级。
- 验收：未登录调用返回 error 事件；免费用户第 4 次被拒。

### 改造 C：Markdown 消毒（1h）

- `npm i dompurify`；`renderedSummary = DOMPurify.sanitize(marked.parse(text))`；问答同理。
- 验收：构造 `<img src=x onerror=alert(1)>` 不再执行。

### 改造 D：补 5 个测试（3h，加分项）

- `pytest + httpx.AsyncClient`：健康检查、注册登录、配额超限、无字幕错误、Webhook 幂等（mock Stripe）。
- mock 掉 yt-dlp 和 DeepSeek，保证离线可跑。
- 验收：`pytest -q` 全绿；CI 一条命令。

### 改造 E：容器化（1h）

- 后端 Dockerfile + 前端 `npm run build` 后由 Nginx 托管；compose 起两个服务。
- 验收：`docker compose up` 后 5173/8000 可用；SSE 不被缓冲。
